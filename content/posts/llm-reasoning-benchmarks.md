每当一个新模型发布，评测榜单上的数字总是最先被拿出来比较。但当越来越多的基准接近“满分”，一个问题变得越来越尖锐：**这些分数真的代表推理能力吗？**

## 一、为什么推理评估如此困难

与知识问答不同，推理能力难以被直接观察。一个模型答对了题目，可能是因为它真的“想明白了”，也可能只是因为它在训练数据中**见过类似的题目**。因此，一个好的推理基准至少需要满足三点：

1. **答案可验证**：最好有唯一、客观的正确答案；
2. **难以记忆**：题目新颖，或能动态生成；
3. **区分度足够**：不会让所有前沿模型都挤在 95 分以上。

## 二、主流基准一览

### 数学推理

- **GSM8K**：约 8,500 道小学数学应用题，曾是推理评测的标杆，如今前沿模型普遍超过 95%，已基本饱和。
- **MATH**：涵盖代数、几何、数论等七个领域的竞赛题，难度显著更高。
- **AIME / 奥赛类题目**：使用每年新出的竞赛题，天然具有一定的抗污染能力，是当前区分顶尖模型的重要依据。

### 代码推理

- **HumanEval / MBPP**：函数级代码生成，同样接近饱和。
- **SWE-bench**：要求模型在真实 GitHub 仓库中定位并修复 issue，更贴近工程实践，也更能体现智能体式的多步推理。
- **LiveCodeBench**：持续收集新发布的编程竞赛题，按时间切分以规避数据污染。

### 科学与专业推理

- **GPQA**：由领域专家编写的研究生级别物理、化学、生物问题，号称“Google 也搜不到答案”。
- **MMLU-Pro**：在 MMLU 基础上增加选项数量、提升难度，降低随机猜对的概率。

### 通用与抽象推理

- **ARC-AGI**：基于网格图案的抽象推理任务，人类可以轻松完成，模型却长期表现不佳，被视为衡量“举一反三”能力的试金石。
- **BIG-Bench Hard**：从 BIG-Bench 中挑选出的 23 个高难度任务，覆盖逻辑推断、时间推理等。

## 三、如何正确地跑一次评测

很多评测结果难以复现，问题往往出在细节上。下面是一个简化的评测脚本，展示了几个关键要素：

```python
import re
from dataclasses import dataclass

@dataclass
class Sample:
    question: str
    answer: str

def extract_answer(text: str) -> str | None:
    """从模型输出中抽取最终答案，约定格式为 \\boxed{...}"""
    match = re.search(r"\\boxed\{([^}]*)\}", text)
    return match.group(1).strip() if match else None

def evaluate(model, dataset: list[Sample], n_samples: int = 4) -> float:
    correct = 0
    for sample in dataset:
        # 多次采样取多数票（self-consistency），降低随机性
        outputs = [model.generate(sample.question, temperature=0.7)
                   for _ in range(n_samples)]
        answers = [a for a in map(extract_answer, outputs) if a]
        if answers and max(set(answers), key=answers.count) == sample.answer:
            correct += 1
    return correct / len(dataset)
```

在报告结果时，务必注明：**提示词模板、采样温度、采样次数、答案抽取规则**，以及是否使用了思维链。这些因素对分数的影响，常常比模型之间的差距还大。

## 四、绕不开的问题：数据污染

数据污染（Data Contamination）是推理评测面临的最大威胁。当测试题出现在预训练语料中，模型的高分就可能只是“背答案”。常见的应对方法包括：

- **时间切分**：只使用模型训练截止日期之后发布的题目；
- **扰动测试**：修改题目中的数字或表述，观察准确率是否显著下降；
- **私有测试集**：不公开题目，只通过接口提交评测；
- **动态生成**：用程序批量生成新题，从根本上杜绝记忆。

> 一个有趣的现象是：在 GSM8K 上把数字换掉之后，部分模型的准确率会下降 10 个百分点以上——这说明它们学到的不完全是“推理”。

## 五、未来趋势

我认为推理评估正在发生三个转变：

1. **从静态到动态**：持续更新的“活”基准会成为主流；
2. **从结果到过程**：不只看答案对不对，还要评估推理链条是否合理、是否忠实；
3. **从单题到任务**：评测对象从单道题目扩展到需要多步规划与工具调用的完整任务。

## 结语

基准是指南针，而不是目的地。当我们过度优化某个分数时，它往往就不再能衡量我们真正关心的东西——这正是古德哈特定律的体现。理解每个基准“测的是什么、测不了什么”，或许比追逐榜单上的数字更重要。
